1. Visión general

La arquitectura de Nomenclaturas del Valle está diseñada para ser simple, económica y escalable. Dado que es un negocio que está arrancando, se prioriza la facilidad de mantenimiento y los costos bajos sobre la complejidad técnica. Se propone una arquitectura web estándar de tres capas: frontend, backend/API y base de datos.

3. Diagrama de capas (descripción textual)

Dado que este es un documento Word, el diagrama se describe en texto. Para visualizarlo gráficamente, ver el Sitemap (Doc 3) o crear el diagrama en Figma/draw.io con esta estructura:

Capa 1 - Cliente (Navegador / Celular)
• El usuario abre la página web en su celular o computador.
• Next.js entrega páginas pre-renderizadas (SSG/SSR) para máxima velocidad.
• El carrito y el estado de sesión se gestionan en el cliente (React Context + localStorage).

Capa 2 - Servidor / API (VPS Hostinger + Dokploy)
• Las API Routes de Next.js manejan: autenticación, consulta de productos, creación de pedidos, integración con Wompi.
• No hay servidor Express separado; la app Next.js corre como un servicio en Dokploy en el puerto 3001. Nginx ya está manejado por Dokploy como proxy inverso.
• El botón de WhatsApp es un widget estático que no requiere backend.

Capa 3 - Servicios externos
• Supabase: base de datos PostgreSQL + autenticación + almacenamiento de imágenes.
• Wompi: procesa el pago y notifica al backend vía webhook cuando el pago es exitoso.
• Dokploy: hospeda el sitio, despliega automáticamente cada actualización y maneja SSL (vía Certbot o auto).

5. Seguridad básica

• Todas las comunicaciones usan HTTPS (SSL con Certbot o el que provea Dokploy automáticamente).
• Las claves de API (Supabase, Wompi) se guardan en variables de entorno, nunca en el código.
• La autenticación usa JWT tokens manejados por Supabase Auth.
• El webhook de Wompi se valida con una firma secreta para evitar fraudes.
• Los datos de tarjeta NUNCA pasan por el servidor propio; los maneja Wompi directamente.
